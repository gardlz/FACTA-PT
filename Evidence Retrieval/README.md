# Evidence Retrieval

This directory contains the code and the results of the evaluation of **question-driven evidence retrieval for fact-checking in European Portuguese**. It compares three ways of querying the LUSA News Corpus: the **complete claim**, the **claim span**, and **verification questions** generated by the 14 language models evaluated in the [Question Generation](../Question%20Generation/) stage.

The experiments assess whether automatically generated verification questions improve the retrieval of relevant evidence relative to declarative queries. The LUSA search infrastructure is kept fixed; the experiment studies **query formulation**, not alternative retrieval models. Only news published **before the source claim's publication date** is eligible.

## Repository structure

```text
src/
  build_gold_questions.py           Prepare CLEVER question/query inputs
  retrieve_lusa.py                  Retrieve ranked LUSA results
  lusa_api.py                       Restricted API client
  dedup_versions.py                 Consolidate reissued LUSA articles
  comparar_queries.py               Retrieval metrics of every query strategy and configuration
  bootstrap_emparelhado_queries.py  Paired bootstrap confidence intervals of the differences
  comum.py                          Shared data paths and utilities
docs/REPRODUCIBILITY.md             Inputs, search protocol and commands in run order
requirements.txt                    Pinned Python dependencies
```

Some file names and command-line values are in Portuguese: `frase` denotes the **complete claim**, and `--query claim` searches the **claim span**.

## Data and access

**Datasets and LUSA news content are not included in this repository.** Obtain CLEVER following the [main repository instructions](../README.md#data) and the applicable access conditions. Paths below are relative to `Evidence Retrieval/`:

```text
../CLEVER/clever.json                  # CLEVER, with the gold questions and the evidence annotations
data/export_evidencias/evidencias.csv  # Top-5 results of every search of every condition
outputs/lusa_top20_claim/              # Ranking of each claim span
outputs/lusa_top20_frase/              # Ranking of each complete claim
outputs/lusa_docs/                     # Cached LUSA documents
```

The stored retrieval files include restricted LUSA material and are **not redistributed**; they may be requested from the authors subject to the LUSA News Corpus access conditions.

Accessing the search API requires an **institutional VPN** and an uncommitted `.env` file in this directory containing `API_URL_LUSA`, `USER_LUSA`, and `PASSWORD_LUSA`. Never commit credentials.

## Installation

Run from `Evidence Retrieval/`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The code runs on **CPU**; no GPU is required.

## Running the experiments

From `Evidence Retrieval/`, with CLEVER available, prepare the query inputs and retrieve the **gold-question**, **claim-span**, and **complete-claim** rankings:

```bash
python src/build_gold_questions.py

# Requires LUSA API access (VPN and credentials)
python src/retrieve_lusa.py
python src/retrieve_lusa.py --query claim --output-dir outputs/lusa_top20_claim
python src/retrieve_lusa.py --query frase --output-dir outputs/lusa_top20_frase
```

`build_gold_questions.py` writes `outputs/gold_questions.jsonl`, one query unit per CLEVER gold question, with its claim span, complete claim and publication date. The three `retrieve_lusa.py` calls search with the gold questions, the claim spans and the complete claims, and write one ranking file per search to `outputs/lusa_top20/`, `outputs/lusa_top20_claim/` and `outputs/lusa_top20_frase/`, respectively, caching the retrieved documents in `outputs/lusa_docs/`. The CLEVER reference documents were collected from the gold-question searches, so the gold questions are not an evaluated condition.

With the **stored retrieval results** listed above available locally, compute the experiment tables and paired bootstrap analysis offline:

```bash
python src/comparar_queries.py
python src/bootstrap_emparelhado_queries.py
```

The metric report is written to `outputs/comparacao_queries.md`, with the values of the two retrieval tables as percentages and their hit counts, and the paired bootstrap analysis to `outputs/bootstrap/`. The inputs of each step, the search protocol and the details of these commands are in [Reproducing the experiments](docs/REPRODUCIBILITY.md).

## How the evaluation works

### Query strategies

| Query strategy | Text submitted to the search |
|---|---|
| **Complete claim** | The full sentence or statement that contains the claim span. |
| **Claim span** | The factual span of the claim selected for verification. |
| **Generated questions** | The verification questions generated for the claim span by one of the 14 models, fine-tuned with **Gold91+Silver1073** (91 manually written CLEVER questions and 1,073 synthetic ClaimPT questions). Each question is a separate search. |

All query strategies search the **LUSA News Corpus**, 1,346,032 documents published by Agência Lusa between 1 January 2016 and 20 April 2026, through the same search API. The API fuses BM25 over headline and content with `intfloat/multilingual-e5-large` semantic search through Reciprocal Rank Fusion (RRF). It was not developed or tuned in this work. The search parameters and the corpus statistics are in [Reproducing the experiments](docs/REPRODUCIBILITY.md#3-search-infrastructure-and-retrieval-protocol).

### Retrieval configurations

A model may generate several questions for a claim span, and each question is a separate search. If every question kept five documents, the generated questions would keep more documents than the two declarative queries. Three configurations therefore separate the effect of the query text from the effect of searching several times:

| Configuration | Generated questions | Complete claim and claim span | What it compares |
|---|---|---|---|
| **Single-search top-5** | Only the first question is used, and its five highest-ranked documents are kept. | One search each, keeping the five highest-ranked documents. | The query texts, with one search for every query strategy. |
| **RRF top-5** | Every question is searched. The five highest-ranked documents of each question are merged with RRF (constant 60), and the five documents with the highest fused score are kept. | As in Single-search top-5. | Whether several questions improve a fixed set of five documents. |
| **Matched retrieval volume** | Every question is searched, and all the distinct documents among the five highest-ranked of each question are kept. | Each extends the five documents it keeps in the top-5 configurations with the next documents of its ranking, up to *B* documents. For each claim span, *B* is the median, over the 14 models, of the number of distinct documents their questions retrieved, with a minimum of five. | Whether documents found by different questions complement each other, with a comparable number of documents. |

The first question is chosen without looking at the retrieval results. The complete claim and the claim span are single searches, so their results are the same in the two top-5 configurations.

### Reference evidence

Retrieval is evaluated on the 100 CLEVER test claim spans of the [Question Generation](../Question%20Generation/) stage, using the questions that each model generated for them. The reference evidence of a claim span is the set of LUSA documents annotated in CLEVER as **Relevant** to it, that is, concerning its factual situation. A Relevant document is **decisive** when it is also annotated **Supported** or **Refuted**; Relevant documents annotated **NEI** (Not Enough Information) are pertinent to the claim span but neither support nor refute it.

| Reference evidence | Claim spans | Claim span-document pairs |
|---|---:|---:|
| Relevant | 83 | 217 |
| Decisive | 56 | 112 |

The other 17 claim spans have no Relevant reference document. Of the 56 claim spans with decisive evidence, 54 have a single reference status, Supported or Refuted; the other two have both Supported and Refuted documents. CLEVER's manually written verification questions are not evaluated as queries: they were used to collect the candidate documents that were then annotated, so evaluating them against the same annotation would be circular.

### Metrics

The metrics are based on Recall: for each claim span, the fraction of its reference documents that are among the documents kept for it.

- **Macro Recall** averages Recall over the claim spans, so every claim span has the same weight.
- **Micro Recall** pools the documents of all claim spans, dividing the reference documents retrieved by all the reference documents, so claim spans with more reference documents weigh more.
- **Relevant** Recall counts all the Relevant reference documents, including those annotated NEI, over the 83 claim spans that have them. **Decisive** Recall counts only the Supported and Refuted documents, over the 56 claim spans that have them.
- **Decisive Claim-Span Coverage (DCSC)** counts verification cases instead of documents: the fraction of the 54 claim spans with a single reference status for which at least one decisive reference document consistent with that status is retrieved.
- **Docs/span** is the average number of distinct documents kept per claim span, over the 83 claim spans with Relevant evidence. It describes the retrieval volume, not its quality.

Precision is not reported, because the evaluation measures how much of the annotated evidence each query strategy recovers. Rank-based metrics such as MRR and MAP are not used, because the configurations that combine several searches do not produce directly comparable single rankings.

The differences between AMALIA-9B-0626-DPO and the two declarative baselines, and between the claim span and the complete claim, come with a 95% confidence interval from a **paired bootstrap** over claim spans: 10,000 resamples with seed 42, in which both strategies are evaluated on the same resampled claim spans, drawn from the 83, 56 or 54 claim spans of each metric. The interval goes from the 2.5th to the 97.5th percentile of the resampled differences; an interval that excludes zero is read as a difference distinguishable from zero. The resampling does not model the dependence between claim spans of the same claim or source article.

## Key findings

- **The claim span is a stronger baseline than the complete claim.** It retrieves more of the reference evidence in every configuration, although the paired bootstrap distinguishes the difference from zero only for Relevant and Decisive Micro Recall.
- **Generated questions generally retrieve more of the reference evidence than the complete claim**, and most models also outperform the claim span in at least part of the evaluation.
- **The clearest gains appear when all the documents retrieved by the questions of a model are kept** (Matched retrieval volume), especially in the number of claim spans for which at least one decisive (Supported or Refuted) document is found.
- **AMALIA-9B-0626-DPO obtains the highest value in the five metrics under Matched retrieval volume** (Relevant and Decisive Macro and Micro Recall, and DCSC). For 32 of the 54 claim spans with a single Supported or Refuted reference status, its questions retrieve at least one decisive document with that status, against 22 for the claim span and 19 for the complete claim. Its advantage is distinguishable from zero in all five metrics against the complete claim, and in three of the five against the claim span.

Taking into account both intrinsic question quality, evaluated in the [Question Generation](../Question%20Generation/) stage, and downstream retrieval performance, **AMALIA-9B-0626-DPO** was selected for the FACT-PT pipeline. The fine-tuned model is available at [liaad/facta-pt-qg-amalia-9b-0626-dpo](https://huggingface.co/liaad/facta-pt-qg-amalia-9b-0626-dpo).
